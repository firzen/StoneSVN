# StoneSVN v1.2.0

English | [简体中文](v1.2.0.zh-CN.md)

Review and resolve SVN conflicts in a side-by-side comparison, with a compact read-only preview in the workspace.

## Conflict comparison

- Compare incoming content with the local result using aligned line numbers, syntax highlighting, synchronized scrolling, and search. In the full comparison, switch between incoming, local, and available base content; choose individual conflict blocks or edit the result before applying it.
- Inspect conflicting SVN properties separately from file content. Applying reviewed property values preserves the file body and unrelated properties. When values cannot be read reliably, keep the original conflict information available for manual resolution.
- Explain tree conflicts using the local and incoming operations. For a file edited locally and deleted by the incoming change, keep the local file or accept the deletion after confirmation. Other tree conflicts require manual file organization before marking them resolved.
- Recheck the reviewed conflict state before applying changes so an outdated preview cannot overwrite content changed since it was loaded. Review and commit the result separately after resolution.

## Workspace and update improvements

- Prioritize conflicted files, including property-only conflicts, at the top of the workspace list. Double-click a conflict or use its Resolve Conflicts icon to open the full comparison; the workspace preview remains read-only.
- Show the current workspace's conflict count in a yellow toolbar badge. Conflict rows keep one resolution entry instead of a duplicate comparison button.
- Show the number of incoming revisions on Update, sharing remote-check results between the toolbar and update page. Background checks retain the last known count when a check fails and identify the failed state.
- Refresh local state with F5 or macOS Command-R without reloading the application. Widen the timeline revision column for longer revision numbers.

Install the SVN CLI separately on each platform. Binary or unreadable conflict content and unsupported property/tree conflict formats may require an external editor or SVN tool. macOS builds are ad-hoc signed and not notarized. Automated checks and packaging do not establish manual installation or startup acceptance on every operating system.
