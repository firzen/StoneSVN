# OrcaSVN v0.6.2 release preparation

English | [简体中文](v0.6.2.zh-CN.md)

Baseline: `v0.6.1` (`5427acf`). Scope includes five subsequent commits and the workspace changes from this round.

## Changes

- Unify light/dark themes, typography, controls, status badges, and scrollbars; add a visual design system and remove duplicate styles.
- Simplify the toolbar and improve narrow navigation, welcome screens, and theme selection.
- Add keyboard operation, focus styles, and accessible labels to workspace status filters and file selection.
- Distinguish a clean workspace from no matching filtered files in all five languages.
- Fix clipped repository/revision text; constrain long content and expose full text in tooltips.
- Reduce page margins from 18px to 6px and panel radii from 18px to 8px.
- Disable WebView developer tools and Tauri's internal toggle command; intercept F12, Ctrl+Shift+I/J/C and macOS equivalents while preserving editing shortcuts. Add shortcut regressions.

Public Chinese/English release notes were added to `.github/workflows/tauri-build.yml`, retaining platform download links.

## Acceptance scope

- Local `npm run check` passed on 2026-09-29: frontend types/build, nine frontend tests, Rust formatting, and 35 Rust tests. Vite still warned about bundles above 500 kB.
- Before release, verify desktop developer shortcuts after restart; long repository/revision text and compact panels in both themes; narrow windows and system scaling.
- Log date-filter display and the original long-path diff scenario remain pending in `todo.md`. This release does not claim acceptance for them.
- The tag workflow builds Windows/macOS/Linux installers; local checks do not replace cross-platform installation validation.

## Historical release steps

1. Complete desktop acceptance and ensure version/configuration/lockfiles are 0.6.2.
2. Commit and push the release scope.
3. Create and push `v0.6.2` to trigger three-platform builds, publish a GitHub Release, and then attempt WinGet publication.
4. Check workflow results, download links, installation, and startup.

Release execution was authorized on 2026-09-29 using the `v0.6.2` tag. GitHub Actions and the Release page are the authority for actual build/publication status. These are historical steps; use the [current release workflow](../releasing.md) for new releases.
