# StoneSVN v1.3.1

- Fix authentication failures with bundled SVN: HTTP(S) repositories now prompt for a username and password inside StoneSVN when cached credentials are unavailable or rejected.
- Keep entered credentials in memory for the current application session, scoped to the server and explicit account. Passwords are passed over standard input rather than process arguments and are not written to settings or the SVN credential cache.
- Preserve server-specific TLS compatibility and certificate exceptions during authentication retries. Cancelling the dialog stops the operation; failed credentials do not cause repeated automatic prompts.
- Checkout, commit, switch, and merge still perform a read-only connection check before making a single mutation attempt. Background incoming-update checks remain silent.
